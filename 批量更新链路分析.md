# Wallabag 标签与阅读状态批量更新链路分析

## 一、整体架构概览

Wallabag 的批量更新功能分为两条主要链路：

| 链路 | 入口 | 适用场景 |
|------|------|----------|
| Web 表单批量操作 | `EntryController::massAction` | 用户在网页列表中勾选条目后统一操作 |
| REST API 批量操作 | `EntryRestController` 多个方法 | 第三方客户端通过 API 批量处理 |

两条链路共享底层的实体模型（Entry/Tag）和 Helper（TagsAssigner），但在事务边界和一致性保证上存在差异。

#### 步骤 1：CSRF 防护（第 57-59 行）

#### 步骤 2：解析操作类型与标签参数（第 61-101 行）

支持四种操作，通过按钮的 `name` 属性判断：

| 按钮 name | 操作 |
|-----------|------|
| （默认） | `toggle-read`：切换阅读状态 |
| `toggle-star` | 切换星标状态 |
| `delete` | 删除条目 |
| `tag` | 批量添加/移除标签 |

**标签语法设计**：支持 `+标签`（添加）和 `-标签`（移除）的前缀语法。

```php
$labels = array_filter(explode(',', (string) $values['tags']), static function ($v) {
    $v = trim($v);
    return '' !== $v;
});
foreach ($labels as $label) {
    $remove = false;
    if (str_starts_with($label, '-')) {
        $label = substr($label, 1);
        $remove = true;
    }
    $tag = $tagRepository->findOneByLabel($label);
    if ($remove) {
        if (null !== $tag) {
            $tagsToRemove[] = $tag;
        }
    } else {
        if (null === $tag) {
            $tag = new Tag();
            $tag->setLabel($label);
        }
        $tagsToAdd[] = $tag;
    }
}
```

关键点：
- 不存在的标签会即时 `new Tag()` 创建（未 persist，依赖后续级联）
- 要移除的标签必须已存在于数据库中，否则跳过

#### 步骤 3：逐条处理条目（第 103-127 行）

```php
if (isset($values['entry-checkbox'])) {
    foreach ($values['entry-checkbox'] as $id) {
        $entry = $this->entryRepository->findById([(int) $id])[0];

        // 权限检查：逐条验证 EDIT 权限
        if (!$this->security->isGranted('EDIT', $entry)) {
            throw $this->createAccessDeniedException('You can not access this entry.');
        }

        if ('toggle-read' === $action) {
            $entry->toggleArchive();
        } elseif ('toggle-star' === $action) {
            $entry->toggleStar();
        } elseif ('tag' === $action) {
            foreach ($tagsToAdd as $tag) {
                $entry->addTag($tag);
            }
            foreach ($tagsToRemove as $tag) {
                $entry->removeTag($tag);
            }
        } elseif ('delete' === $action) {
            $this->eventDispatcher->dispatch(new EntryDeletedEvent($entry), EntryDeletedEvent::NAME);
            $this->entityManager->remove($entry);
        }
    }

    // 关键：所有条目处理完成后，统一一次 flush
    $this->entityManager->flush();
}
```

#### 步骤 4：重定向返回（第 132-134 行）

```php
$redirectUrl = $this->redirectHelper->to($request->query->get('redirect'));
return $this->redirect($redirectUrl);
```

### 3.3 一致性保证：单 flush 策略

这是整个方法最关键的设计——**所有条目在内存中修改完毕后，才调用一次 `entityManager->flush()`**。

这意味着：
- 所有 SQL INSERT/UPDATE/DELETE 在同一个数据库事务中提交
- 任何一条条目在处理中抛出异常（如权限拒绝），整个批处理会回滚
- Doctrine 的 UnitOfWork 会计算所有变更并一次性发送到数据库

#### 标签多对多关联


#### 标签操作方法（带去重保护）

```php
public function addTag(Tag $tag): void
{
    // 第一层检查：Doctrine Collection 的 contains（基于对象哈希）
    if ($this->tags->contains($tag)) {
        return;
    }

    // 第二层检查：基于 label 字符串比较（防止同 label 不同对象的重复）
    foreach ($this->tags as $existingTag) {
        if ($existingTag->getLabel() === $tag->getLabel()) {
            return;
        }
    }

    $this->tags->add($tag);
}

public function removeTag(Tag $tag): void
{
    if (!$this->tags->contains($tag)) {
        return;
    }

    $this->tags->removeElement($tag);
    $tag->removeEntry($this); // 双向同步
}
```

## 五、Helper 层：TagsAssigner —— 标签分配的核心逻辑

文件：[TagsAssigner.php](file:///d:/fz/0601-1/solo-dogfeeding/code/44-wallabag/src/Helper/TagsAssigner.php)

```php
public function assignTagsToEntry(Entry $entry, $tags, array $entitiesReady = [])
{
    $tagsEntities = [];

    if (!\is_array($tags)) {
        $tags = explode(',', $tags);
    }

    // 处理尚未 flush 的标签实体（用于批量导入场景）
    $tagsNotYetFlushed = [];
    foreach ($entitiesReady as $entity) {
        if ($entity instanceof Tag) {
            $tagsNotYetFlushed[$entity->getLabel()] = $entity;
        }
    }

    foreach ($tags as $label) {
        $label = trim(mb_convert_case((string) $label, \MB_CASE_LOWER));

        if ('' === $label) {
            continue;
        }

        // 优先使用内存中未 flush 的标签
        if (isset($tagsNotYetFlushed[$label])) {
            $tagEntity = $tagsNotYetFlushed[$label];
        } else {
            $tagEntity = $this->tagRepository->findOneByLabel($label);

            if (null === $tagEntity) {
                $tagEntity = new Tag();
                $tagEntity->setLabel($label);
            }
        }

        // 只有关系不存在时才添加
        if (false === $entry->getTags()->contains($tagEntity)) {
            $entry->addTag($tagEntity);
            $tagsEntities[] = $tagEntity;
        }
    }

    return $tagsEntities;
}
```

设计要点：
- `entitiesReady` 参数解决批量导入场景中「同批次新建标签尚未入库但需要复用」的问题
- 标签统一转小写 trim，保证幂等性
- 与 `Entry::addTag` 的双重去重机制配合，彻底避免重复关联

## 六、Repository 层：跨条目批量标签操作

文件：[EntryRepository.php](file:///d:/fz/0601-1/solo-dogfeeding/code/44-wallabag/src/Repository/EntryRepository.php#L448-L474)

```php
public function removeTag($userId, Tag $tag): void
{
    $entries = $this->getSortedQueryBuilderByUser($userId)
        ->innerJoin('e.tags', 't')
        ->andWhere('t.id = :tagId')->setParameter('tagId', $tag->getId())
        ->getQuery()
        ->getResult();

    foreach ($entries as $entry) {
        $entry->removeTag($tag);
    }

    $this->getEntityManager()->flush();
}

public function removeTags($userId, $tags): void
{
    foreach ($tags as $tag) {
        $this->removeTag($userId, $tag);
    }
}
```

注意：这里的 `removeTag` 方法内部自带一次 `flush()`，所以 `removeTags` 会对每个标签分别 flush，不是原子操作。

```php
#[Route(path: '/api/entries/tags/lists.{_format}', name: 'api_post_entries_tags_list', methods: ['POST'])]
public function postEntriesTagsListAction(Request $request, EntryRepository $entryRepository, TagsAssigner $tagsAssigner)
{
    $list = json_decode($request->query->get('list', '[]'));
    $results = [];

    foreach ($list as $key => $element) {
        $entry = $entryRepository->findByUrlAndUserId($element->url, $this->getUser()->getId());
        $results[$key]['url'] = $element->url;
        $results[$key]['entry'] = $entry instanceof Entry ? $entry->getId() : false;

        if (false !== $entry && !(empty($element->tags)) && $this->authorizationChecker->isGranted('TAG', $entry)) {
            $tagsAssigner->assignTagsToEntry($entry, $element->tags);
            $this->entityManager->persist($entry);
            $this->entityManager->flush(); // ⚠️ 每条独立 flush
        }
    }

    return $this->sendResponse($results);
}
```

### 8.1 从所有条目中删除多个标签

`deleteTagsLabelAction`（第 114-134 行）：

```php
#[Route(path: '/api/tags/label.{_format}', name: 'api_delete_tags_label', methods: ['DELETE'])]
public function deleteTagsLabelAction(Request $request, TagRepository $tagRepository, EntryRepository $entryRepository)
{
    $tagsLabels = $request->request->get('tags', $request->query->get('tags', ''));
    $tags = $tagRepository->findByLabelsAndUser(explode(',', $tagsLabels), $this->getUser()->getId());

    if (empty($tags)) {
        throw $this->createNotFoundException('Tags not found');
    }

    $entryRepository->removeTags($this->getUser()->getId(), $tags); // 内部对每个 tag flush 一次
    $this->cleanOrphanTag($tags); // 删除无条目的孤立标签

    $json = $this->serializer->serialize($tags, 'json');
    return (new JsonResponse())->setJson($json);
}
```

### 8.2 孤立标签清理

```php
private function cleanOrphanTag($tags): void
{
    if (!\is_array($tags)) {
        $tags = [$tags];
    }

    foreach ($tags as $tag) {
        if (0 === \count($tag->getEntries())) {
            $this->entityManager->remove($tag);
        }
    }

    $this->entityManager->flush();
}
```

## 九、事务与一致性保证机制深度分析

### 9.1 各操作路径的事务边界对比

| 操作路径 | 事务边界 | 一致性等级 | 异常行为 |
|----------|----------|------------|----------|
| `EntryController::massAction` | **所有条目共享一次 flush** | ✅ 原子性：全成功或全回滚 | 任一异常，全部回滚 |
| `EntryRestController::postEntriesTagsListAction` | **每条独立 flush** | ⚠️ 非原子：部分成功部分失败 | 已处理的条目不会回滚 |
| `EntryRepository::removeTag` | **每个标签一次 flush** | ⚠️ 非原子：标签级独立提交 | 后续标签失败不影响已处理的 |
| `TagRestController::deleteTagsLabelAction` | **每个标签 flush + 最后清理 flush** | ⚠️ 多步提交 | 中间失败会留下部分处理结果 |

### 9.2 Web 端 massAction 的原子性实现

```php
foreach ($values['entry-checkbox'] as $id) {
    $entry = $this->entryRepository->findById([(int) $id])[0];

    if (!$this->security->isGranted('EDIT', $entry)) {
        throw $this->createAccessDeniedException('...'); // ⚠️ 抛出异常会触发回滚
    }
    // 修改实体...
}

$this->entityManager->flush(); // 所有变更一次性写入
```

Doctrine ORM 的工作机制：
1. 所有 `find`/`persist`/`remove` 操作只修改内存中的 UnitOfWork
2. 只有调用 `flush()` 时才开启数据库事务并执行 SQL
3. flush 过程中任何 SQL 错误都会导致整个事务回滚

### 9.3 幂等性与去重保护

| 层级 | 保护机制 | 作用 |
|------|----------|------|
| Tag 实体 | `setLabel` 自动转小写 | 标签大小写不敏感 |
| Entry::addTag | 两层 contains 检查（对象哈希 + label 字符串） | 防止同一标签被重复关联 |
| TagsAssigner | label 转小写 trim + contains 检查 | API 调用时的幂等性保证 |
| DB 层 | `tag.slug` unique 约束 | 最终兜底，防止标签表出现重复 |

### 9.4 权限控制策略

逐条权限检查而非批量检查：

```php
if (!$this->security->isGranted('EDIT', $entry)) {
    throw $this->createAccessDeniedException('You can not access this entry.');
}
```

优点：细粒度控制，防止用户通过构造请求 ID 越权操作他人条目
代价：在 massAction 中，如果某个条目无权访问，整个批次全部回滚

### 9.5 双向关联同步

Entry 与 Tag 之间是双向 ManyToMany：
- `Entry::addTag($tag)` 只维护 Entry 侧的 Collection
- `Entry::removeTag($tag)` 同时调用 `$tag->removeEntry($this)` 保证双向同步

注意：`addTag` 没有同步调用 `$tag->addEntry($this)`，依赖 Doctrine 在 flush 时通过拥有方（Entry 侧）的关联来维护中间表。
